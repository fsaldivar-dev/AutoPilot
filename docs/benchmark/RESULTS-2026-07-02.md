## Metodologia

- Cada invocacion es un proceso frio del CLI completo — misma
  penalizacion de arranque para todas las herramientas. Es la
  latencia real que ve un usuario por comando.
- `tap` es semantico (label `Explorea` en la pantalla de auth):
  incluye fetch del arbol + resolucion + tap.
- `swipe` mide `swipe up`; entre corridas se restaura la posicion
  con un swipe down via adb puro (no medido).
- AdbLegacyBridge corre con el agente detenido (`agent stop`):
  Android permite un solo cliente UiAutomation (#135).
- Maestro tambien usa UiAutomator, asi que corre con el agente
  detenido. Cada operacion es `maestro test <flow>.yaml` (o
  `maestro hierarchy` para tree) e incluye el arranque de la JVM,
  identico a como se invoca desde una terminal.
- `ping` no tiene equivalente en Maestro.
- Percentiles nearest-rank sobre las corridas exitosas; los fallos
  se reportan como `(ok/N)`.
